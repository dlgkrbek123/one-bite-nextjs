라우트그룹

- 각기 다른 경로를 가지는 페이지 파일을 묶는다
- ()로 감싼 폴더 만들어서 정의

------------------------------------------------------------------------

- 추가되기전의 문제점
  - hydration을 위해 전달하는 bundle에 모든 컴포넌트가 포함될 필요는 없다.
  - 상호작용이 있는 애들만 실행되면 될듯 => hydration필요없는애들을 굳이 실행
  - page router떄는 bundle에 해당 페이지의 모든 컴포넌트가 담김
  - TTI가 늦어짐
=> 분류를 해서 개선하자

앱라우터에서는 기본적으로 모든 컴포넌트가 서버 컴포넌트
필요한 부분만 클라이언트 컴포넌트로 정의하자

리액트 서버 컴포넌트
- 서버측에서만 실행되는 컴포넌트
- 사전렌더링할때는 모든 컴포넌트 실행
- hydration될때 서버 컴포넌트는 제외하여 번들에 전달 실행
- useEffect등의 브라우저 실행코드가 존재해선 안된다.

클라이언트 컴포넌트
- 일반적인 리액트 컴포넌트
- "use client"
- 상호작용이 필요할떄만 지정
- 사전 렌더링과 hydration에서 2번 실행됨
- 내부에서 서버컴포넌트를 import할 수 없다.
  - 클라이언트 컴포넌트 내부에 서버 컴포넌트가 있으면 클라이언트 컴포넌트로 자동으로 바꿔줌
  - render props로 회피할수 있긴함

사전렌더링
- 서버 컴포넌트를 먼저 실행하여 RSC Payload(string)가 산출됨
  - 직렬화된 서버 컴포넌트
- 클라이언트 컴포넌트 실행하여 html로 합성

------------------------------------------------------------------------

초기접속 이후 페이지 이동시 페이지 라우터에서는 bundle만 전달했는데,
앱라우터에서는 RSC Payload도 전달한다.

페이지는 빌드시 static or dynamic으로 분류된다.
기본적으로는 static으로 분류하려고 하지만 동적인 인자가 있는 등의 경우에 dynamic으로 분류한다.
이 분류에 따라 프리페칭시 전달되는 요소도 달라진다. (rsc payload + bundle(유형별로 옵셔널 ))

export default async function SearchPage({
  searchParams,
}: {
  searchParams: Promise<{ q: string }>;
}) {
  const { q } = await searchParams;

  return <div>검색 페이지 q: {q}</div>;
}

export default async function BookDetailPage({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;

  return <div>book/[id] {id} </div>;
}
