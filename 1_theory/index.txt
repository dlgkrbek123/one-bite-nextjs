nextjs
- 리액트 프레임워크 + DLC
- vercel이 오픈소스로 개발

사전 렌더링
- 브라우져 요청에 사전에 렌더링이 완료된 HTML을 응답하는 렌더링 방식
  1. 유저가 페이지 요청
  2. 서버에서 컴포넌트 코드를 실행시켜 html로 변환
  3. html 응답 (인터랙션 불가)
  4. bundle을 전달
  - 응답받은 html과 bundle을 연결하여 상호작용 추가
  - 이 과정을 hydration이라고 부름


- 초기에 컨텐츠가 있는 html이 내려옴 (완성된 화면)
- 이 화면은 인터랙션 못함 (js가 해주는거임)
- 상호작용이 가능해진 시점을 TTI라고 함 
- 초기 페이지 접속 이후에는 CSR과 유사하게 요청함 (이젠 bundle, chunk 아니까)

- FCP는 개선되었고... 이후 페이지 이동은 빠르게 전환되는 장점은 승계함



CSR
- 리액트의 기본적인 렌더링 방식
- 말그대로 브라우저에서 런타임에 화면을 렌더링하는 방식

1. 빈 html을 응답
2. js가 로드되어 라우터에 맞는 페이지 컴포넌트 렌더링

- 초기 렌더링 이후 페이지 전환은 매우 신속함
- 다만 전체번들을 다 로드하는게 한번에 부담스럽긴함(초기 렌더링 오래걸림)

FCP (first contentful paint)
- 요청 시작시점으로부터 컨텐츠가 화면에 처음 나타나는 시간
- 이탈률과 직결
